# 功能目录与依赖边界

- 新增或重构的独立功能放在 `src/features/<feature>/`，按实际需要使用 `data/`、`domain/`、`components/`、`pages/` 和功能样式文件；不要为了形式预建空目录。
- `domain/` 保存题型、生成器、评分适配、解锁等纯 TypeScript 逻辑，不依赖 React、DOM、浏览器存储或具体页面。
- `data/` 保存功能私有的静态内容和解析逻辑；共享数据只有被两个以上功能真实复用时才提升到 `src/data/`。
- `components/` 只负责该功能的渲染与交互；`pages/` 负责组合功能组件和连接应用状态。根目录 `src/pages/` 可保留薄路由入口或兼容导出，不重复实现业务。
- 依赖方向保持 `pages → components → domain/data`；`domain` 不得反向导入组件或页面。跨功能共享逻辑放在明确的共享模块中，不从另一个功能的页面或组件深层导入。
- 可脚本生成的内容实现 `ScriptedExerciseGenerator<Request, Result>` 等显式接口。生成器可以使用类封装随机源和策略，但可独立计算的规则仍优先写成纯函数，禁止用无状态类仅充当命名空间。
- 功能测试与被测 domain 模块放在同一功能目录；至少覆盖数量、唯一性、稳定 ID、边界输入和关键业务不变量。
- 迁移既有模块时可以保留短小的兼容入口并写明用途；新代码必须直接导入 feature 内实现，不得继续依赖兼容入口形成新的反向耦合。
